# دليل التشغيل والصيانة — منصة لغتي

> للفريق التقني أو المسؤول عن الخادم في المدرسة/الإدارة. كل الأوامر من مجلد المشروع على الخادم.

---

## 1) الاستضافة الموصى بها

| البند | التوصية |
|---|---|
| الموقع | **مزود سحابي داخل المملكة** مرخّص من هيئة الاتصالات والفضاء والتقنية (STC Cloud، أو مراكز بيانات المزودين العالميين داخل المملكة) — لتحقيق اشتراطات **نظام حماية البيانات الشخصية** وضوابط **الهيئة الوطنية للأمن السيبراني** بشأن إقامة البيانات |
| الخادم | Ubuntu 22.04/24.04، **2 vCPU / 4GB RAM / 40GB SSD** تكفي لمدرسة (حتى ~600 طالبة). أضيفي 1GB RAM لكل 300 طالبة إضافية |
| البرمجيات | Docker Engine + Docker Compose فقط |
| الشبكة | المنفذان 80 و443 مفتوحان للعموم، وكل ما عداهما مغلق (منفذ القاعدة **لا يُفتح**) |
| النطاق | سجل DNS من نوع A يشير لعنوان الخادم (مثال: `lughati.school.edu.sa`) |

> **Netlify/Vercel** يصلحان للتجربة فقط (البيانات خارج المملكة، ولا PDF على الخادم، ويلزم تخزين S3). راجعي `DEPLOY.md`.

## 2) التثبيت الأول (مرة واحدة)

```bash
git clone <المستودع> lughati && cd lughati

# 1. الأسرار (تُحفظ نسخة منها خارج الخادم في خزنة كلمات مرور)
mkdir -p deploy/secrets
openssl rand -hex 24      > deploy/secrets/db_password
openssl rand -base64 48   > deploy/secrets/backup_passphrase
chmod 600 deploy/secrets/*

# 2. إعدادات الإنتاج
cp deploy/env.production.example deploy/app.env
#   NEXTAUTH_URL=https://<النطاق>
#   NEXTAUTH_SECRET=$(openssl rand -base64 32)
#   FIELD_ENCRYPTION_KEY=$(node -e "console.log(require('crypto').randomBytes(32).toString('base64'))")
#   DATABASE_URL=postgresql://lughati:<كلمة مرور db_password>@db:5432/lughati
echo "DOMAIN=lughati.school.edu.sa" > .env      # يقرؤه docker compose

# 3. التشغيل (الخادم يرفض الإقلاع ويتوقف إن كان أي سر ضعيفاً أو مفتاح التطوير، ويذكر السبب في السجل)
docker compose up -d --build
docker compose logs app | grep "\[env\]"   # يجب ألا يظهر شيء
docker compose ps                     # كل الخدمات healthy
curl https://<النطاق>/api/v1/health   # {"status":"ok","db":"ok"}
```

عند أول إقلاع تُطبَّق ترحيلات قاعدة البيانات تلقائياً، ويحصل Caddy على شهادة HTTPS تلقائياً.

### إنشاء أول حساب
القاعدة فارغة في الإنتاج (**لا تشغّلي `db:seed`** — فهو يمسح البيانات ويعبئ بيانات تجريبية). أنشئي المدرسة ومدير النظام مرة واحدة:

```bash
docker compose exec app node deploy/create-admin.cjs "اسم المدرسة" "الإدارة العامة للتعليم بـ..." admin@school.edu.sa "اسم المدير"
```

يطبع كلمة مرور مؤقتة. يرفض العمل إن وُجد أي حساب مسبقاً. ثم يدخل المدير ← يفعّل التحقق الثنائي ← ينشئ حسابات القائدة والمعلمات والمشرفة من «المستخدمون والصلاحيات»، ثم هيّئي العام الدراسي (آمن للتكرار ولا يمسح شيئاً):

```bash
docker compose exec app node deploy/setup-year.cjs --year "1448هـ" \
  --term1 2026-08-23:2027-01-07 --term2 2027-01-17:2027-06-10 --sections "أ,ب,ج"
```

يُنشئ قاموس المهارات، والسنة، والفصلين الدراسيين بأسابيعهما ومخطط الأوزان الافتراضي، والشُّعب برموز دخول الطالبات. التواريخ من التقويم الدراسي الرسمي.

## 3) ⚠️ الأسرار الحرجة

| السر | إن ضاع | إن تسرّب |
|---|---|---|
| `FIELD_ENCRYPTION_KEY` | **لا يمكن قراءة أرقام الهوية والجوالات والملاحظات الصحية إطلاقاً** — ولا تنفع النسخ الاحتياطية | قراءة الحقول الحساسة لمن يملك نسخة القاعدة |
| `backup_passphrase` | النسخ الاحتياطية غير قابلة للاستعادة | فك تشفير النسخ |
| `NEXTAUTH_SECRET` | تُسجَّل خروج الجميع فقط (يُولَّد جديد) | تزوير الجلسات — غيّريه فوراً |
| `db_password` | يُعاد ضبطه من داخل الحاوية | الوصول للقاعدة (لكنها غير مكشوفة للشبكة) |

**احفظي `FIELD_ENCRYPTION_KEY` و`backup_passphrase` في خزنة كلمات مرور منفصلة عن الخادم وعن مكان النسخ الاحتياطية**، ولدى شخصين على الأقل.

## 4) النسخ الاحتياطي (قاعدة 3-2-1)

حاوية `backup` تعمل تلقائياً:
- **يومياً 02:00** بتوقيت الرياض ← `backups/daily/` (آخر 30 نسخة)
- **أسبوعياً الجمعة** ← `backups/weekly/` (آخر 12)
- **نهاية كل فصل دراسي** (يدوياً، تُحفظ 5 سنوات):
  ```bash
  docker compose exec backup bash /deploy/backup.sh term
  ```
- **نسخة بعيدة**: اضبطي `BACKUP_S3_URI=s3://<حاوية-في-منطقة-أخرى>` في `.env` (يدعم أي مزود متوافق مع S3).

كل نسخة مشفّرة (AES-256) ومعها بصمة SHA-256 تكشف أي تلف. السجل: `backups/backup.log`.

### اختبار الاستعادة (شهرياً — إلزامي)
```bash
ADMIN_DATABASE_URL=postgresql://lughati:<pw>@localhost:5432/postgres \
BACKUP_DIR=./backups BACKUP_PASSPHRASE_FILE=deploy/secrets/backup_passphrase \
FIELD_ENCRYPTION_KEY=<المفتاح> ./scripts/restore-test.sh
```
يستعيد أحدث نسخة إلى قاعدة مؤقتة، ويتحقق من الجداول والأعداد وسجل الترحيلات و**فك تشفير عينة بالمفتاح المحفوظ**، ثم يحذفها. احفظي التقرير في سجل الصيانة.

> **المستهدف:** فقدان بيانات ≤ يوم واحد (النسخة اليومية) — ويمكن تقليصه إلى 15 دقيقة بتفعيل أرشفة WAL في قاعدة مُدارة. زمن الاستعادة ≤ 4 ساعات.

### الاستعادة الفعلية بعد كارثة
1. أوقفي التطبيق: `docker compose stop app`
2. أنشئي قاعدة جديدة واستعيدي إليها (لا تستعيدي فوق القاعدة الحالية):
   ```bash
   docker compose exec db createdb -U lughati lughati_restored
   ./scripts/restore.sh backups/daily/db-<الأحدث>.dump.enc postgresql://lughati:<pw>@localhost:5432/lughati_restored
   ```
3. بدّلي `DATABASE_URL` إلى `lughati_restored` ← `docker compose up -d app` ← تحققي ← سجّلي الحادثة.
4. الملفات المرفوعة: فكّي `files-<التاريخ>.tar.gz.enc` بنفس عبارة المرور إلى حجم `uploads`.

## 5) التحديث إلى إصدار جديد
```bash
./scripts/backup.sh daily     # أو: docker compose exec backup bash /deploy/backup.sh daily
git pull
docker compose up -d --build app    # الترحيلات تُطبَّق تلقائياً عند الإقلاع
docker compose logs -f app          # «Applying migration ...» ثم «Ready»
```
الترحيلات إضافية ومتسلسلة (`prisma/migrations`) ولا تُستخدم `db push` في الإنتاج أبداً.

**تثبيت قائم أُنشئ بـ `db push` قبل الترحيلات:** نفّذي مرة واحدة `npx prisma migrate resolve --applied 0001_init`.

## 7) حوادث شائعة

| العرض | السبب المرجّح | الحل |
|---|---|---|
| الطاقم لا يستطيع الدخول «القفل 15 دقيقة» | 5 محاولات خاطئة | القائدة: «المستخدمون» ← «فك القفل» |
| فقدت معلمة جوالها (التحقق الثنائي) | — | القائدة: «إعادة ضبط التحقق الثنائي» |
| طالبة «توقفي قليلاً» | 5 محاولات صور خاطئة | المعلمة: صفحة الفصل ← توليد رمز جديد لها |
| «محاولات كثيرة» لفصل كامل | حد IP منخفض خلف NAT المدرسة | ارفعي `RATE_LIMIT_STUDENT_LOGIN` / `RATE_LIMIT_ROSTER` |
| زر «تنزيل PDF» يعطي «غير مفعّل» | صورة بلا Chromium أو `PDF_ENGINE=browser` | استخدمي «طباعة ← حفظ كـ PDF»، أو أعيدي البناء بالصورة الافتراضية |
| التطبيق يتوقف فور الإقلاع «إعدادات البيئة غير صالحة» | سر ضعيف/مفتاح التطوير/رابط غير https | السجل يذكر المفتاح المعني: `docker compose logs app` |
| الألعاب لا تعمل دون اتصال | الموقع ليس HTTPS أو لم تُفتح الألعاب متصلاً | تأكدي من HTTPS، وافتحي الألعاب مرة واحدة متصلة |

## 8) دورة البيانات

- **بداية العام:** أنشئي السنة والفصول الدراسية، استوردي التوزيع الرسمي (توزيع المنهج ← استيراد) وقوائم الطالبات من «نور»، ولّدي بطاقات دخول الطالبات.
- **نهاية كل فصل:** اعتماد الدرجات لكل فصل ← تصدير ملف «نور» ← نسخة `term`.
- **انتقال طالبة/تخرّجها:** أرشفة (تبقى بياناتها). **طلب محو من ولي الأمر:** القائدة ← ملف الطالبة ← تصدير البيانات (تسلَّم لولي الأمر) ← حذف نهائي. كلاهما مسجّل في التدقيق.
- **الاحتفاظ:** يوصى بحذف بيانات الطالبات المؤرشفات بعد مضي المدة التي تقرّها سياسة الإدارة التعليمية.
