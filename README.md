# منصة رياضيات 1448 — الصفان الأول والثاني الابتدائي

منصة تعليمية إلكترونية متكاملة لمعلمي الرياضيات للصفين الأول والثاني
الابتدائي، مبنية وفق التنظيم الفصلي لمنهج وزارة التعليم السعودية للعام
الدراسي 1448هـ.

هذا المستودع يحتوي على **نسخة عمل فعلية (Working MVP)** تُشغَّل وتُختبر
مباشرة، تغطي البنية الكاملة للمتطلبات العشرة المطلوبة، بالإضافة إلى
**مقترح التنفيذ والجدول الزمني** لتطوير هذه النسخة إلى نظام إنتاجي جاهز
للاعتماد في المدارس.

## 2) الستاك التقني

| الطبقة | التقنية | السبب |
|--------|---------|-------|
| إطار العمل | **Next.js 14 (App Router) + TypeScript** | أداء عالٍ، Server Components لتقليل الحمل على المتصفح، ملائم لبيئة مدرسية بشبكة محدودة |
| التنسيق | **Tailwind CSS** بدعم RTL كامل + خط **Tajawal** | تصميم عربي أنيق ومتجاوب بسرعة تطوير عالية |
| قاعدة البيانات | **Prisma ORM** فوق **SQLite** (تطوير) / **PostgreSQL** (إنتاج) | مخطط بيانات type-safe وهجرات منظمة، وتبديل قاعدة البيانات بسطر واحد |
| المصادقة | **NextAuth.js** (Credentials + JWT) + **bcrypt** | تحكم كامل بالصلاحيات دون الاعتماد على خدمة خارجية، بيانات الطلاب لا تغادر الخادم |
| الرسوم البيانية | **Recharts** | مكتبة خفيفة تدعم RTL وتصلح للوحات مدرسية |
| استيراد Excel | **SheetJS (xlsx)** | يدعم `.xlsx/.xls/.csv` من المتصفح مباشرة دون رفع الملف الخام لخادم خارجي |
| التحقق من المدخلات | **Zod** | تحقق صارم من جميع مدخلات الـ API لمنع حقن البيانات |

### لماذا هذا الاختيار تحديداً؟
- **تكلفة تشغيل منخفضة**: يعمل على استضافة واحدة (Vercel/VPS) دون خدمات
  خارجية مدفوعة إلزامية.
- **بيانات الطلاب محلية بالكامل**: لا اعتماد على مزودي طرف ثالث لحفظ
  الدرجات أو الأسماء، وهو أمر مهم لخصوصية بيانات الأطفال.
- **قابلية النمو**: الانتقال من SQLite إلى PostgreSQL لا يتطلب تغيير أي
  سطر في منطق التطبيق، فقط تغيير `DATABASE_URL` وإعادة تشغيل الهجرات.

      worksheets/                 قائمة/إنشاء/معاينة وطباعة أوراق العمل
      students/                  إدارة الطلاب + استيراد Excel
      gradebook/                 دفتر الدرجات والتصحيح
      reports/                   لوحة الشرف والتقارير
      admin/                     لوحة التحكم الإدارية
    api/                         نقاط الـ API (REST داخل Next.js Route Handlers)
  components/                    مكونات واجهة قابلة لإعادة الاستخدام
  lib/                           منطق الأعمال (تصحيح، توليد أسئلة، تقارير...)
  middleware.ts                  حماية المسارات حسب الدور (RBAC)
prisma/
  schema.prisma                  مخطط قاعدة البيانات الكامل

### نموذج الأدوار (RBAC)
- **مدير النظام (ADMIN)**: كل الصلاحيات + لوحة الإدارة.
- **معلم (TEACHER)**: إدارة أوراق العمل، الطلاب، دفتر الدرجات، التقارير.
- **طالب (STUDENT)**: عرض خريطة المنهج والتقارير الخاصة به فقط (الأساس
  جاهز؛ واجهة تسليم الإجابات الذاتية للطالب موصوفة في خطة التوسعة).

## 4) التشغيل السريع (Quick Start)

```bash
# 1) تثبيت الحزم
npm install

# 2) إعداد المتغيرات البيئية
cp .env.example .env
# عدّل NEXTAUTH_SECRET إلى قيمة عشوائية طويلة

# 3) إنشاء قاعدة البيانات (SQLite محلياً)
npm run db:push

# 4) تعبئة بيانات أولية (خريطة المنهج + حسابات تجريبية + فصل وطلاب تجريبيون)
npm run db:seed

# 5) تشغيل بيئة التطوير
npm run dev
```

افتح `http://localhost:3000` وسجّل الدخول بأحد الحسابين التجريبيين:

| الدور | البريد الإلكتروني | كلمة المرور |
|-------|--------------------|-------------|
| مدير النظام | `admin@school.sa` | `ChangeMe123!` |
| معلم | `teacher@school.sa` | `Teacher123!` |

> غيّر كلمتي المرور فوراً بعد أول تشغيل في أي بيئة حقيقية.

## 5) دليل استخدام سريع للمعلم

1. **خريطة المنهج**: من القائمة الجانبية، راجع وحدات الفصل الحالي وعدّل
   التقسيم الزمني إن لزم (زر «تعديل» داخل كل وحدة).
2. **إنشاء ورقة عمل**: *أوراق العمل ← ＋ ورقة/اختبار جديد*، اختر الصف
   والوحدة، استخدم «التوليد التلقائي» لمسائل الجمع/الطرح أو أضف أسئلة
   يدوياً بأي نوع، ثم احفظ.
3. **الطباعة**: من صفحة الورقة اضغط «طباعة / تصدير PDF» — سيفتح مربع
   طباعة المتصفح، اختر «حفظ كـ PDF» للحصول على ملف A4 جاهز.
4. **استيراد الطلاب**: *الطلاب ← استيراد من Excel*، ارفع الملف، تحقق من
   مطابقة الأعمدة، عاين الصفوف، ثم أكّد الاستيراد.
5. **تكليف فصل بورقة**: من صفحة الورقة اختر الفصل وتاريخ التسليم واضغط
   «تكليف الفصل».
6. **التصحيح**: *دفتر الدرجات*، اختر التكليف، اضغط «تصحيح» أمام اسم
   الطالب، أدخل إجاباته (تُصحَّح الأسئلة الموضوعية تلقائياً) وامنح درجة
   يدوية للمسائل المفتوحة، ثم احفظ.
7. **لوحة الشرف والتقارير**: تُحدَّث تلقائياً فور التصحيح، ويمكن تصفيتها
   حسب الفصل، ومشاهدة تقدم كل طالب عبر الزمن.

### تدريب المعلمين (خطة مقترحة)
- **جلسة 1 (45 دقيقة)**: تسجيل الدخول، التنقل العام، خريطة المنهج.
- **جلسة 2 (60 دقيقة)**: إنشاء ورقة عمل/اختبار، الطباعة، استيراد الطلاب.
- **جلسة 3 (45 دقيقة)**: التصحيح، دفتر الدرجات، قراءة التقارير ولوحة
  الشرف.
- مواد داعمة: هذا الدليل + تسجيل شاشة قصير لكل جلسة (يُنتج في مرحلة
  التسليم النهائي).

## 6) الأمان (المُنفَّذ حالياً)

- تجزئة كلمات المرور بـ **bcrypt** (لا تُخزَّن كلمات مرور نصية أبداً).
- جلسات **JWT** موقّعة عبر NextAuth مع صلاحيات مسارات محمية بـ `middleware.ts`.
- تحقق صارم من جميع مدخلات الـ API عبر **Zod** قبل لمس قاعدة البيانات.
- **سجل تدقيق (Audit Log)** يُسجّل كل عملية إنشاء/تعديل/حذف حساسة (من
  نفّذها، متى، وعلى أي عنصر) — متاح من لوحة الإدارة.
- صلاحيات مبنية على الأدوار (RBAC) على مستوى الواجهة والـ API معاً، وليس
  الواجهة فقط.
- **Next.js محدَّث لآخر إصدار مرقّع أمنياً (15.5.x)** لسد الثغرات الحرجة
  المُعلنة مؤخراً في محرك الإطار نفسه.

> **ثغرة معروفة غير مُغلقة من المصدر (xlsx/SheetJS):** مكتبة استيراد
> ملفات Excel المستخدمة (`xlsx`) لديها ثغرتا Prototype Pollution و ReDoS
> معروفتان بدون تصحيح رسمي متاح حتى تاريخه. المخاطر مخفَّفة في هذا
> التطبيق لأن التحليل يتم **بالكامل داخل متصفح المعلم على الملف الذي
> يرفعه هو بنفسه** (لا يُرسل الملف الخام لأي خادم)، وليس على مدخلات من
> مستخدمين غير موثوقين عبر الشبكة. يُنصح بعدم فتح ملفات Excel من مصادر
> غير موثوقة، وفي حال رغبت بإزالة هذه المخاطرة كلياً يمكن استبدال
> `src/components/StudentImportModal.tsx` بمكتبة بديلة مثل `exceljs`
> عند التحويل للإنتاج.

## 7) متطلبات الأمان والنسخ الاحتياطي لبيئة الإنتاج (موصى بها)

هذه بنود يجب تفعيلها قبل الإطلاق الفعلي في مدرسة، وهي خارج نطاق هذا الـ MVP:

- **HTTPS إلزامي** + رؤوس أمان (CSP, HSTS) عبر الاستضافة أو Reverse Proxy.
- **PostgreSQL مُدار** (مثل Supabase أو Amazon RDS) بدلاً من SQLite، مع
  **نسخ احتياطي تلقائي يومي** ونسخة أسبوعية بعيدة (Off-site).
- **تشفير بيانات الطلاب الحساسة في حالة السكون** (Encryption at rest) —
  متاح افتراضياً في معظم مزودي PostgreSQL المُدارين.
- **تحديد معدل الطلبات (Rate limiting)** على مسارات تسجيل الدخول لمنع
  محاولات التخمين.
- **مصادقة ثنائية (2FA)** لحسابات المدير على الأقل.
- **نسخ احتياطي للملفات المرفوعة** (شعارات، صور أسئلة) إن استُخدم تخزين
  سحابي (S3-compatible)، بسياسة استبقاء لا تقل عن 30 يوماً.
- **سياسة خصوصية بيانات الطلاب** متوافقة مع نظام حماية البيانات الشخصية
  السعودي (PDPL)، تشمل: أقل قدر من البيانات، حق الحذف، تحديد صلاحية
  الوصول لبيانات كل فصل للمعلم المسؤول عنه فقط.

| المرحلة | المحتوى | المدة التقديرية |

التسليم الأساسي، بافتراض توفر مشرف تربوي لمراجعة المحتوى بالتوازي مع
التطوير.

### فريق التنفيذ الموصى به

- مصمم UI/UX بدوام جزئي — المراحل 2، 5.
- مشرف/معلم رياضيات لمراجعة المحتوى المنهجي — المراحل 1، 6، 7.
